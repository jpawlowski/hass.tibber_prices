# Demo dashboard and documentation screenshots

Everything needed to reproduce the screenshots in the docs and the README from the dev instance (`./scripts/develop`).
The dashboard comes from the `get_dashboard_yaml` action; design notes live in `planning/dashboard-ux-plan.md` (git-ignored, local).

## Tibber demo account

Tibber provides a public demo token with a fictional home ("Vitahuset", shown as "Winterfell Castle 1", Sweden, SEK):

```text
3A77EECF61BD445F47241A5A36202185C35AF3AF58609E19B53F3A8872AD7BE1-1
```

Add the integration in the dev instance with this token. Screenshots must only ever show this demo home, never a real one.

## Setup (once)

1. Install **ApexCharts Card**, **Config Template Card** and **TabDeck Card** from HACS in the dev instance (only `tibber-demo-apex` uses them).
2. Create a long-lived access token (profile → Security) and store it in `config/.ha_token` (git-ignored), or export it as `HA_TOKEN`.

## Energy data for the energy card (optional)

```bash
./scripts/docs/demo/setup-solar [--backfill] [--dry-run]
```

The energy card (`tibber-prices-energy-card`) reads the solar and battery sources of the Energy dashboard. The script sets one up in the dev instance: Forecast.Solar at the demo home's location (Stockholm, 25° / south / 10 kWp) if there is none, a "Solar production (demo)" energy sensor (a Riemann sum helper over Forecast.Solar's "Estimated power production - now"), a demo home battery and grid connection (four meters as external statistics for the last days, imported again at every run), and the Energy dashboard's solar, battery and grid sources. Other sources there stay, and a grid connection that exists is not replaced. `--backfill` imports the finished hours of today as statistics, so the production curve isn't empty at first. The production is the forecast's own, so the two curves lie on each other: it shows the look of the card, not real data. Forecast.Solar's free API allows about 12 requests per hour and IP, so run it on the dev instance only, not in CI.

## Render the dashboard

```bash
./scripts/docs/demo/render-dashboard
```

The script calls `tibber_prices.get_dashboard_yaml` for the demo home and saves the views as the UI dashboard `tibber-demo` (created on the first run). The demo is therefore exactly what users get from the action. A second call with `chart_card: apexcharts` saves `tibber-demo-apex` (not in the sidebar), for the screenshots of the ApexCharts alternative. It also saves `tibber-cards`: the integration's own cards, one view each, from `cards.yaml` next to the script (placeholders `entity:<key>` and `device:<key>` resolve to the demo home), for the screenshots of the Dashboard Cards page. Run it again after changing the template, the labels or the chart generator, then reload the page.

- Template: `custom_components/tibber_prices/services/dashboard_template.yaml` (placeholders are explained at its top).
- Labels: the `dashboard` area of `custom_components/tibber_prices/custom_translations/<lang>.json`. Names are short because the heading already gives the context ("Lowest price" under "Today", not "Today's Lowest Price").
- Charts: generated by `get_apexcharts_yaml` with `level_type: level`, so the chart colors match the price level shown in the verdict, and with best and peak price highlights (peak periods stay hidden until toggled in the legend).

Labels follow the language HA runs in (`homeassistant.language` in `config/configuration.yaml`, English for the docs); `--lang de` asks for another one. States stay in the language of the browser profile.

## Take screenshots

```bash
uv venv /tmp/pw && uv pip install --python /tmp/pw/bin/python playwright
/tmp/pw/bin/python -m playwright install chromium
/tmp/pw/bin/python scripts/docs/demo/screenshots.py /tmp/shots            # all shots, light + dark
/tmp/pw/bin/python scripts/docs/demo/screenshots.py /tmp/shots overview   # a single shot
```

The script clicks the tabs before each shot and crops to the dashboard content (no sidebar, no user name), or to one card or the window a click opens (`card-*` shots). The frontend is shown in English whatever the token user's profile language is (the script answers the frontend's language lookup in the browser; the profile stays as it is).

Shots go to the docs as JPG (quality 85, at most 1600 px wide), light as `<name>.jpg`, dark as `<name>-dark.jpg`: the overview as `docs/user/static/img/dashboard-overview*.jpg`, the ApexCharts tabs (`chart-*`, from `tibber-demo-apex`) under `docs/user/static/img/charts/`, the cards under `docs/user/static/img/cards/` without the `card-` prefix (`forecast-phone` puts `card-forecast-mobile` and `card-forecast-details` side by side; `chart-phone` is `card-chart-mobile`). Shots of the Tomorrow tab are skipped while tomorrow's prices are not available yet.
